1. Executive Summary

ThreatLens is a single-file Python cybersecurity application that enables security professionals, students, and researchers to investigate Indicators of Compromise (IOCs) using the VirusTotal v3 threat intelligence API. The application provides an interactive, browser-based dashboard built with Streamlit, offering real-time reputation lookups, multi-engine detection statistics, color-coded risk classification, actionable defensive recommendations, and downloadable investigation reports in CSV, JSON, and PDF formats.

All application logic — API integration, indicator validation, risk analysis, SQLite history management, chart rendering, and report generation — is contained within a single source file (app.py, approximately 1,450 lines). The application runs fully in demonstration mode without any API credentials, making it suitable for offline portfolio presentations and classroom demonstrations.

Key achievements: (1) correct VirusTotal v3 API integration for all four IOC categories; (2) a transparent, threshold-based risk engine; (3) professional-grade PDF report generation via ReportLab; (4) a polished blue-and-white Streamlit dashboard with Plotly charts; and (5) a persistent SQLite investigation history with search and filtering.

2. Project Overview

2.1 Objectives

  • Provide a practical tool for investigating IOCs encountered during security incidents or threat hunting activities.
  • Demonstrate integration with a real, production threat intelligence API (VirusTotal v3).
  • Deliver a professional, interactive dashboard that communicates threat data clearly to both technical and non-technical audiences.
  • Generate audit-ready investigation reports in CSV, JSON, and PDF formats.
  • Operate transparently — never inventing data, never misrepresenting demonstration results as live intelligence.

5. Indicator Validation and Classification

The classify_indicator() function accepts a raw string and returns a three-tuple: (normalized_indicator, type_key, error_message). It applies validation in a deliberate precedence order to avoid ambiguity:

  1. URL detection — strings starting with http:// or https:// are parsed with urllib.parse.urlparse(). A missing netloc triggers an error.
  2. IP address detection — ipaddress.ip_address() is called; ValueError indicates a non-IP string. Both IPv4Address and IPv6Address are handled.
  3. Hash detection — regex patterns match exact hex lengths: 32 (MD5), 40 (SHA-1), 64 (SHA-256). Matched hashes are lowercased for normalization.
  4. Domain detection — a compiled regex enforces RFC-compliant label and TLD structure.
  5. Rejection — any string that passes none of the above tests returns an empty type key and a descriptive error message displayed in the UI.
Normalization is deliberately minimal: only hash strings are lowercased. The application never opens URLs, downloads files, or resolves DNS entries during the validation step.

6. VirusTotal API Integration

6.1 Endpoint Mapping

IOC TypeVirusTotal v3 Endpoint
IPv4 / IPv6GET /api/v3/ip_addresses/{ip}
DomainGET /api/v3/domains/{domain}
URLGET /api/v3/urls/{base64url(url), no padding}
File Hash (MD5 / SHA-1 / SHA-256)GET /api/v3/files/{hash}

URLs are encoded as base64url without padding per the VirusTotal v3 specification: base64.urlsafe_b64encode(url.encode()).rstrip(b'=').decode().

6.2 Response Normalization

The lookup_virustotal() function extracts a normalized result dictionary from the raw API response. The normalized structure always contains the same keys regardless of IOC type, allowing all downstream components (risk engine, charts, reports, history) to consume a single consistent schema. Fields extracted include: last_analysis_stats (malicious, suspicious, harmless, undetected, timeout counts), last_analysis_date (UTC string), reputation (for IPs and domains), and per-engine verdicts filtered to flagging engines only.

6.3 Error Handling

HTTP error codes are mapped to user-facing messages: 401 (invalid API key), 404 (indicator not found), 429 (rate limit exceeded), and all other 4xx/5xx codes. Network-level exceptions (Timeout, ConnectionError, RequestException) are caught and converted to descriptive error strings. API keys are never included in any error message.

7. Risk Assessment Engine

The classify_risk() function applies transparent, threshold-based classification. Thresholds are defined as named module-level constants (MALICIOUS_THRESHOLD = 3, SUSPICIOUS_ENGINE_THRESHOLD = 2) and can be adjusted without modifying classification logic.

ConditionRisk LevelMeaning
malicious engines ≥ 3 🔴 MALICIOUS Confirmed threat — immediate defensive action required
malicious ≥ 1 or suspicious ≥ 2 🟠 SUSPICIOUS Treat with caution — investigate further before trusting
malicious = 0 and suspicious = 0 🟢 NO SIGNIFICANT DETECTIONS No engines flagged — does not guarantee safety
total engines = 0 🔵 INCONCLUSIVE No engine results available for this indicator
API lookup did not succeed ⚪ LOOKUP FAILED Service unavailable, invalid key, or network error

The function returns both a risk level key and a plain-English explanation stating exact detection counts and the threshold crossed. Recommended defensive actions from get_recommended_actions() combine both risk level and IOC type for targeted guidance (e.g. a malicious domain includes a DNS sinkholing step not present for a malicious file hash).

8. Streamlit Dashboard

The dashboard is organized as a three-tab layout: Analyze Indicator, Investigation History, and About. This separates the primary workflow from secondary functions.

8.1 Analysis Tab

Presents: (1) a privacy notice warning that indicators may be disclosed to VirusTotal; (2) an API connection status badge; (3) a text input with live type detection; (4) an Analyze Indicator submit button; and after submission: (5) the risk badge, five summary metric cards, Plotly donut and engine bar charts, expandable technical details, expandable recommended actions, and three download buttons.

8.2 Theming

Custom CSS is injected via st.markdown(unsafe_allow_html=True). Palette: background #f0f4f8, sidebar #1a3a5c (dark navy), accent #2c6fad (medium blue). Risk colors follow traffic-light conventions: red for malicious, orange for suspicious, green for clean, blue for inconclusive.

8.3 Charts

A donut pie chart shows detection category distribution; a horizontal bar chart lists each engine that flagged the indicator. Both render only when total_engines > 0 to prevent empty chart errors, and use transparent backgrounds for clean dashboard integration.

9. Local Investigation History

Investigation records are persisted to a local SQLite database (threatlens_history.db) using Python's standard library sqlite3 module. The database is created automatically on first run via CREATE TABLE IF NOT EXISTS. Only metadata is stored — no raw API response payloads, no API keys.

The history tab provides a search input (substring match on the indicator column), a dropdown type filter, and a Clear All History button that issues DELETE FROM investigations and triggers st.rerun().

10. Report Generation

Three downloadable report formats are served via st.download_button(). All are generated in memory (io.StringIO / io.BytesIO) — no temporary files are written to disk.

FormatContentsPrimary Use Case
CSV Two-row flat table (header + data) with all fields including risk explanation. SIEM import, spreadsheet analysis
JSON Nested object: report metadata, indicator details, provider info, analysis statistics, risk assessment, flagging engine verdicts, recommended actions. Programmatic processing, SOAR ingestion
PDF Multi-page ReportLab Platypus report: branded header, metadata table, color-coded risk block, detection stats table, flagging engines table, numbered actions list, privacy disclaimer. Audit documentation, stakeholder reporting

Report filenames: threatlens_{indicator}_{timestamp}.{ext}, indicator sanitized to 40 safe characters. Demonstration-mode reports carry a prominent warning banner in all three formats.

11. Security & Privacy Design

ControlImplementation Detail
API key protectionKeys read exclusively from environment variables or Streamlit secrets. Never stored in SQLite, written to disk, displayed in the UI, logged, or included in error messages.
No file uploadOnly hash strings are accepted for file investigations. No file content is ever sent to any external service.
No URL fetchingURLs are submitted as strings for reputation lookup only. The application never opens, fetches, or renders suspicious URLs.
Safe HTTP timeoutsAll API requests use a 20-second timeout (VT_TIMEOUT = 20) to prevent hanging connections.
Minimal data storageOnly investigation metadata is persisted to SQLite. Raw API response payloads are discarded after processing.
Privacy noticeA visible warning is displayed before every external lookup, informing users that submitted indicators may be disclosed to VirusTotal.
Input validation before submissionIndicators are validated and typed before any network request is made. Malformed inputs are rejected with a descriptive error in the UI.

12. Demonstration Mode

When no VIRUSTOTAL_API_KEY is present, ThreatLens switches automatically to demonstration mode. A distinct set of pre-defined sample datasets — one per IOC type — is returned without making any API call. The sample data represents realistic detection distributions (e.g. a high-detection IP, a clean SHA-1, a moderately detected URL) and exercises all application code paths identically to a live lookup.

Transparency at every level: the sidebar shows a yellow warning badge, the analysis tab displays a blue info banner, result sections carry a "Demonstration Mode" label, and all generated reports include a prominent disclaimer. The distinction between live intelligence and demonstration data is never ambiguous.

13. Installation & Configuration

13.1 Requirements

Python 3.11 or later. Tested on Windows 11 (x64, 8 GB RAM), compatible with macOS and Linux. No GPU or machine learning framework required. A free VirusTotal API key is optional (free tier: 4 req/min, 500 req/day).

13.2 Installation Steps

  1. Clone the repository: git clone https://github.com/your-username/threatlens.git
  2. Create a virtual environment: python -m venv .venv
  3. Activate it (Windows PowerShell): .venv\Scripts\Activate.ps1
  4. Install dependencies: pip install -r requirements.txt
  5. Set the API key (optional, current session): $env:VIRUSTOTAL_API_KEY = "your_key_here"
  6. Launch the dashboard: streamlit run app.py

13.3 Persistent API Key (Windows)

[System.Environment]::SetEnvironmentVariable("VIRUSTOTAL_API_KEY", "your_key_here", "User") # Restart your terminal after running this command.

14. Limitations & Future Work

14.1 Current Limitations

LimitationDetail
Coverage gapsVirusTotal aggregates results from partner vendors. Zero detections do not guarantee an indicator is safe — zero-day threats, novel malware, and regional threats may go undetected.
Data stalenessThe last_analysis_date field reflects when VirusTotal last analyzed the indicator, which may be days or weeks before the lookup.
API rate limitsThe free tier allows 4 requests per minute and 500 per day. Exceeding these limits causes HTTP 429 errors, which the application handles gracefully with a clear message.
Single providerOnly VirusTotal is integrated. Cross-validation with additional intelligence sources is not available in the current version.

14.2 Proposed Future Enhancements

  • Additional providers — AlienVault OTX, Shodan, AbuseIPDB, and Cisco Talos following the same normalized result schema.
  • Bulk IOC analysis — Accept a CSV or text file of multiple indicators and process them sequentially with rate-limit awareness.
  • MITRE ATT&CK mapping — Cross-reference flagging engine verdicts against the MITRE ATT&CK framework.
  • STIX/TAXII export — Export investigation results in STIX 2.1 format for SIEM and SOAR platform ingestion.
  • Configurable thresholds — Allow users to adjust risk classification thresholds through the dashboard UI.

15. Conclusion

ThreatLens demonstrates that a fully functional, professionally presented cybersecurity tool can be built within a single Python source file without sacrificing code quality, security, or usability. The application successfully integrates with the VirusTotal v3 API, applies a transparent risk assessment methodology, and delivers results through a polished interactive dashboard with multi-format report generation.

The project fulfills all stated objectives: genuine API integration, honest treatment of demonstration data, local investigation persistence, professional PDF reporting, and a clean dashboard suitable for portfolio presentation. The architecture is designed for extensibility — adding a second intelligence provider requires implementing one lookup function and one demo dataset, with all downstream rendering, classification, and report generation code reused without modification.

ThreatLens represents a solid foundation for a production-grade threat intelligence workbench and illustrates practical skills in Python development, REST API integration, cybersecurity analysis workflows, and data visualization.
